# Bounded memory audit of the agent-gossip app (read-only)

This file lists each collection in `crates/agent-gossip/src` that lives as long as the process, with its bound, its worst-case bytes, and its proposed drop rule.

## Facts checked

Engine paths refer to the pinned checkout `~/.cargo/git/checkouts/habilis-network-d7689bcdcb2fc477/f7cd9bb` (rev in `Cargo.lock:1808`). Engine files are `habilis-network-util/src/...` unless noted.

- Frame cap `MAX_MESSAGE_SIZE` = 3840 B: **holds**. `consts.rs:45`.
- Logical body cap `MAX_LOGICAL_BODY_BYTES` = 64 MiB: **holds**. `consts.rs:71`. The app refuses larger text at `broadcast_params.rs:647` and `broadcast_params.rs:1202`. Sealed ceiling 96 MiB at `consts.rs:78` and `broadcast_params.rs:1970`.
- Surfaced ring = 1000 events with full bodies: **holds**. Count: `tuning.rs:66` and `tuning.rs:82`. Bodies: `output_event.rs:25-27` (`Message` holds `Box<Authored>`) and `verified.rs:363-367` (`Authored` holds an `Arc<Message>`).
- `TASKS_PER_PEER_CAP` = 64 and `TASKS_CAP` = 1024: **holds for values** (`tuning.rs:108`, `tuning.rs:115`). **Enforced only on remote offers**: `node.rs:1131-1136` and `node.rs:1172`, through `admit_new_task` at `task_record.rs:443-455`. The initiator path inserts with no check: `task_record.rs:471-499`, reached from `a2a_app.rs` `adopt_returned_task`. `TASKS_CAP` counts terminal records too (`tuning.rs:111-114`). `TASKS_PER_PEER_CAP` counts live records only (`tuning.rs:101-107`).
- `TaskRecord` holds no leg bodies: **holds** (`task_record.rs:72-133`). The one text field, `waiting`, is capped to `TASK_LABEL_MAX_CHARS` = 120 chars at `status_update_params.rs:509-515` (`tuning.rs:121`).
- A live task stays open while one leg arrives every 24 h: **holds only for gaps under 24 h**. The silence test is strict `>` at `task_record.rs:141-146`.
- `TASK_SKILL_SILENCE_MAX_SECS` stops only the keepalive beats: **does not hold**. The sweep cancels a task once both sides stop sending beats and the peer is silent for `TASK_TIMEOUT_SECS` = 120 s (`task_record.rs:804-812`, `tuning.rs:18`, `tuning.rs:26`). For a peer that never beat, the silence cap alone sets `peer_gone` (`task_record.rs:806`).
- Only the count caps bound tasks: **does not hold**. A task with no leg for more than 24 h is cancelled and then reaped (`task_record.rs:804-834`). Count caps bound only tasks that keep getting legs.
- `own_legs` (`a2a_app.rs:165`) and `unsent_legs` (`a2a_app.rs:169`) have no cap: **holds**. Push sites: `a2a_app.rs:274`, `broadcast_params.rs:1559`, `1585`, `1704`, `1710`, `2632`. No length check at any site.
- `orphan_blobs` has `evict_at`: **holds** (`a2a_app.rs:141`, `a2a_app.rs:678-684`). It has no count cap: `orphan_blob` pushes with no check (`a2a_app.rs:441-447`).
- `late_cancels` empties each sweep: **holds**. `take_late_cancels` (`a2a_app.rs:437-439`) runs in `tick_task_sweep` (`task_record.rs:735`), called from `on_tick` (`a2a/node.rs:138`). The tick period is the engine `SWEEP_INTERVAL` = 10 s (`tuning.rs:190`). I did not trace the full tick wiring.
- `call_blobs` is reaped with its task: **holds**. `take_call_blobs` removes entries of reaped tasks (`a2a_app.rs:451-462`), called at `task_record.rs:765`. A live task keeps its groups, and no per-task cap exists (`a2a_app.rs:385`, `a2a_app.rs:424`).

Not checked: the engine blob store cap enforcement (`consts.rs:174`). The engine cap sizes are read from source, not from a live build.

- Unmarked `tuning.rs:NNN` cites mean `crates/agent-gossip/src/a2a/tuning.rs`. Cites marked "engine" mean the pinned habilis-network checkout.
- Out of scope: `crates/agent-gossip-test-fixtures`. It is a dev-dependency only, so it does not ship in the binary. Out of scope: `crates/agent-gossip-wasm-client`. It sits outside `crates/agent-gossip/src`.
- No app-owned document collection exists in scope. Engine document caps (`consts.rs:116`, `consts.rs:122`) are engine-owned. No keyframe design exists, so no document drop rule is set.
- No app-owned dead-peer table exists in scope. The engine `QUIET_CAP` (`tuning.rs:671`) is engine-owned.
- Transient collections not listed: `reader_asks.rs:104` (lives under 500 ms), `served.rs:39`, `card.rs:273`, MCP result vectors, and `doctor.rs` vectors.
- Engine IPC request queues are engine-owned. I did not trace them.

## NONE rows ranked by worst-case bytes

Each count is unbounded, so the rank uses worst case per item. Ties go to the row with less drain.

1. R10 `unsent_legs`: 192 MiB per item (`frames` 96 MiB + `cache` 96 MiB, estimate).
2. R17 `MeshSession.events_rx`: 64 MiB per `Message` event. Never drained in directory, advertiser, or ticket sessions.
3. R19 `TicketDirectory.events_rx`: 64 MiB per event at the body cap. Drained only by the `discover` command.
4. R9 `own_legs`: 64 MiB per item. Head-of-line wait can stall the queue.
5. R11 surfaced tap: 64 MiB per event. Drained each loop turn.

Next: R18 `Directory.events_rx` at about 1 KB per event, and R6 `call_blobs` at about 64 B per group.

## Main findings

- The initiator path (`task_record.rs:471-499`) skips the `TASKS_CAP` gate. A registry can exceed `TASKS_CAP`.
- The directory, advertiser, and ticket sessions keep an unread unbounded `MeshSession` event channel (R17). This grows for the life of the process.
- Ticket length is not capped (R19, R20). The `TicketListings` byte bound depends on the body cap.
- The surfaced ring (R12) has a count cap but no byte cap. Its worst case is about 67 GB.
- `own_legs` and `unsent_legs` (R9, R10) have no count cap. One slow dial holds the head of the queue.
